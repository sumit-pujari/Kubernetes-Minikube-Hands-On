# ☸️ Kubernetes — Production Cluster Management & KOPS

## 📌 How to Manage Hundreds of Kubernetes Clusters?

In the previous topics, we learned:

- What Kubernetes is
- Why Kubernetes is required
- Kubernetes architecture
- Kubernetes control plane and worker nodes
- Kubernetes distributions

Now the important question is:

> **How do DevOps engineers actually create and manage Kubernetes clusters in production?**

Running Kubernetes locally using tools such as Minikube is useful for learning, but production Kubernetes environments are much more complex.

In production, DevOps engineers may need to manage:

- Cluster creation
- Cluster configuration
- Cluster upgrades
- Cluster deletion
- Networking
- Storage
- Security
- Cloud resources
- High availability
- Multiple Kubernetes clusters

This is where **Kubernetes distributions and cluster-management tools** become important.

## 2. Why is Production Kubernetes Different?

A production cluster may contain:
```
                 Kubernetes Cluster

        ↓                ↓                ↓
```

## 3. Kubernetes Cluster Lifecycle

A DevOps engineer is not responsible only for deploying applications.

They may also need to manage the entire lifecycle of the Kubernetes cluster.

The lifecycle can be represented as:
```
              Kubernetes Cluster
                     |
        ┌────────────┼────────────┐
        ↓            ↓            ↓
      Create      Upgrade       Delete
        |
        ↓
   Configure
        |
        ↓
     Maintain
```
Important lifecycle operations include:

**1. Cluster Creation**

- Create the Kubernetes infrastructure.

**2. Cluster Configuration**

Configure:

- Networking
- Storage
- DNS
- Access
- Nodes
- Kubernetes components

**3. Cluster Upgrade**

- Upgrade Kubernetes versions and related components.

**4. Cluster Maintenance**

Maintain:

- Nodes
- Security
- Networking
- Storage
- Kubernetes components
  
**5. Cluster Deletion**

- Remove the cluster and its associated infrastructure when it is no longer required.

## 10. KOPS
**What is KOPS?**

**KOPS** stands for:

**Kubernetes Operations**

KOPS is a tool used to create and manage Kubernetes clusters, particularly on AWS.

It can help with Kubernetes cluster lifecycle operations such as:

- Cluster creation
- Cluster configuration
- Cluster updates
- Cluster upgrades
- Cluster deletion

The important idea is:
```
KOPS
  |
  ├── Create Cluster
  ├── Configure Cluster
  ├── Update Cluster
  ├── Upgrade Cluster
  └── Delete Cluster
```
Instead of manually configuring every infrastructure component, KOPS automates much of the process.

## 13. How KOPS Stores Cluster Configuration

KOPS uses an object storage bucket to store cluster state/configuration.

In AWS, this is commonly an S3 bucket.

Conceptually:

             KOPS
               |
               ↓
             S3
               |
       Cluster Configuration
               |
               ↓
       Kubernetes Cluster

The S3 bucket is important because KOPS uses it as a source of cluster state/configuration.

---
## 14. Why is S3 Required?

Suppose KOPS manages a cluster.

It needs to store information about the cluster configuration.

Instead of keeping everything only on the local machine:
```
Laptop
  |
  └── Cluster configuration
```
KOPS can store cluster state in S3:

             KOPS
               |
               ↓
        S3 State Store
               |
               ↓
       Cluster Configuration

This allows the cluster state to be stored externally and accessed as required.

## 15. AWS IAM Permissions

When working with AWS resources, KOPS needs permission to create and manage resources.

The AWS identity used by the CLI therefore needs appropriate IAM permissions.

If an administrator-level AWS identity is used, the required permissions may already be available.

For a restricted IAM user, permissions need to be configured according to the operations KOPS must perform.

Examples discussed include permissions around:

- S3
- VPC
- EC2
- Other AWS resources required by the cluster
  
**Important Security Note**

Do not blindly give AdministratorAccess in a real production environment.

Use the principle of least privilege:
```
User
  ↓
Only required permissions
  ↓
Required AWS resources
```

**Creating a Kubernetes Cluster Using KOPS**

KOPS provides commands to create a Kubernetes cluster.

The general idea is:
```
kops create cluster \
  --name=<cluster-name> \
  --state=s3://<bucket-name> \
  --zones=<availability-zone> \
  --node-count=<number> \
  --node-size=<instance-type> \
  --master-size=<instance-type>
```
The exact options can vary depending on the KOPS version and AWS setup.

**IMP Parameter**
| Parameter       | Purpose                     |
| --------------- | --------------------------- |
| `--name`        | Kubernetes cluster name     |
| `--state`       | KOPS state store            |
| `--zones`       | AWS availability zone(s)    |
| `--node-count`  | Number of worker nodes      |
| `--node-size`   | Worker node instance size   |
| `--master-size` | Control-plane instance size |

## 21. Important Interview Questions
**Q1. What is KOPS?**

Answer:

KOPS stands for Kubernetes Operations. It is a tool used to create and manage Kubernetes clusters, especially on AWS. It supports cluster lifecycle operations such as creation, configuration, updates, upgrades, and deletion.

**Q2. What is the difference between KOPS and kubectl?**

Answer:

kops is primarily used to manage the Kubernetes cluster itself, including its lifecycle.

kubectl is used to communicate with an existing Kubernetes cluster and manage Kubernetes resources such as Pods, Deployments, Services, and ConfigMaps.
```
kops
 ↓
Cluster Management

kubectl
 ↓
Resource Management
```
**Q3. What is the difference between Minikube and a production Kubernetes cluster?**

Answer:

Minikube is primarily intended for local development and learning. A production cluster is designed to handle real workloads and typically requires multiple nodes, networking, storage, high availability, security, monitoring, and other infrastructure components.

**Q4. What is EKS?**

Answer:

Amazon Elastic Kubernetes Service (EKS) is AWS's managed Kubernetes service. It reduces the operational burden of managing Kubernetes control-plane infrastructure and integrates Kubernetes with AWS services.

**Q5. Why do we need an S3 bucket with KOPS?**

Answer:

KOPS uses an S3 bucket as a state store for storing cluster configuration/state information.
```
KOPS
  ↓
S3 State Store
  ↓
Cluster State
```
**Q6. What is the purpose of kops create cluster?**

Answer:

It creates the desired configuration for a Kubernetes cluster. The configuration can then be applied using an update operation.

Conceptually:
```
kops create cluster
        ↓
Cluster configuration
```
**Q7. What does kops update cluster --yes do?**

Answer:

It applies the cluster configuration and creates/updates the required infrastructure resources.
```
Configuration
     ↓
kops update cluster --yes
     ↓
AWS Infrastructure
```
**Q8. Why is Route 53 used?**

Answer:

Route 53 is AWS's DNS service. KOPS can use DNS and Route 53 for cluster-related domain configuration and DNS management.

**Q9. Can Minikube be used for production?**

Answer:

Minikube is primarily intended for local development and learning. It is not the typical choice for production Kubernetes workloads.

**Q10. Why are Kubernetes distributions used?**

Answer:

Distributions and managed Kubernetes platforms provide additional tooling, integrations, operational support, security features, lifecycle management, and cloud/enterprise capabilities around Kubernetes.
